# Controller register evidence

The HUG application most closely fits a PIC18F87K22-family device with 64 or 128 KiB of program flash. The observed port layout favors the 64-pin parts. The four family members still compatible with this evidence are PIC18F66K22 and PIC18F67K22 (64 pins), and PIC18F86K22 and PIC18F87K22 (80 pins). Selecting PIC18F66K22 as an assembler profile reproduces the instruction encoding. A package marking or device ID is needed to identify the physical part. [Microchip device comparison and register map](https://ww1.microchip.com/downloads/en/DeviceDoc/39960d.pdf)

| Firmware evidence | Peripheral interpretation |
|---|---|
| At `0xD616–0xD63E` the firmware clears bit 5 of `0xFA1`, writes `0x05` to `0xF6A`, polls the interrupt flag, transfers again, tests bit 0 of `0xF68`, reads `0xF6A`, and ends by changing a GPIO output. | On K22 this is an MSSP2 synchronous serial transaction using PIR2.SSP2IF, SSP2STAT.BF and SSP2BUF. K90 places LCD segment data at `0xF6A`. This transaction distinguishes the two otherwise similar families. [K22 register map](https://ww1.microchip.com/downloads/en/DeviceDoc/39960d.pdf) and [K90 register map](https://ww1.microchip.com/downloads/en/DeviceDoc/39957c.pdf) |
| `0xD712–0xD750` loads high/low bytes into bank-F offsets `0x3F/0x3E`, starts the timer at `0xF3D.0`, waits on `0xFBA.3`, and stops it. | Timer7 high/low, T7CON and PIR5.TMR7IF match. This peripheral exists on the larger flash variants. The image already reaches byte address `0xDF7F`, beyond the 32 KiB parts. |
| `0xD6CE–0xD710` writes via `0xF61–0xF63`, `0xF7E` and `0xF7F`. `0xD3BA–0xD3F4` uses the same key register before modifying `0xF5F.5` and writing time fields via `0xF5C/0xF5D`. | The EEPROM registers, real-time clock write enable, and clock-value window match K22. These features also occur on K90. |
| `0x98AA–0x98AE` clears ANCON0/1/2. `0x98BC–0x9982` initializes TRISA through TRISG and associated latches. For F it handles bits 1–7, and for G it handles bits 0–4. It then proceeds directly to peripheral setup. | The port-by-port initialization matches a design using ports A through G. An 80-pin device also exposes H and J. The decoded assembly contains zero access-bank operands or explicit MOVFF operands targeting PORTH/J, LATH/J or TRISH/J (`0xF87/88`, `0xF90/91`, `0xF99/9A`), and zero direct banked accesses with bank F set in the same basic block. Indirect addressing, inherited bank selection, and unresolved words limit this negative evidence. An 80-pin controller can leave H/J unused. |

The candidate models share this part of the peripheral map. The application occupies less than 64 KiB and the HEX contains no device-ID or configuration records. The physical LH40 reported application revision 126 over USB, matching the revision in the archive. Identifying its controller still requires a package marking or device ID.
