# Charging indicator waveform

In the archived LH80 image, modes `0x02` and `0x12` request pattern 13 with both channels enabled. The starting request uses red 17 and green 37 (`0x5220–0x5236`). On each fade update the firmware writes a calculated value to the red PWM register, CCPR9L at `0xF44`, and writes **37** to the green PWM register, CCPR8L at `0xF47` (`0x78B8–0x78C2`). The red calculation at `0x77F8–0x78B6` is approximately `trunc(max(1, (4.19995 − V) × 30 + 1) + phase / 2)`, where `V` is the three-byte battery reading at `0x2D0`. The compiler uses 24-bit floating-point arithmetic. For a steady reading of 4.2 V, the red register ranges from 1 to 11 while green stays at 37. These numbers are PWM register values. The perceived color and brightness depend on the LEDs and their driver.

The phase starts at 20 (`0x75E8–0x75F4`), falls by one per update to 0, then rises by one to 20 (`0x7702–0x775E`). One full cycle takes **40 updates**. Both mode-entry paths select the short Timer5 interval (`0x61F8` and `0x63C8`). With the configured 1:1 prescaler and a 32,768 Hz secondary oscillator, the preload `0xFE99` gives 359 ticks or 10.96 ms per overflow (`0x99F0–0x99F2`, `0xD1BA–0xD1C6`, `0x19B0–0x19D0`). If each overflow wakes the idle foreground loop once, the nominal cycle is **0.44 seconds**. The foreground calls the indicator before sleeping (`0x6524–0x655A`), so extra wakeups or processing can change the observed period. This timing estimate and the physical LED output have not been measured on an LH40. [Microchip PIC18F87K22 family register map](https://ww1.microchip.com/downloads/en/DeviceDoc/39960d.pdf)
